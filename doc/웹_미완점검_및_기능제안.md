# 웹 파트 미완 점검 + 기능 제안

> 작성 2026-09-05 · 대상: `web/` (Next.js 16 App Router) 현재 커밋 `64abf7e`
> 목적: ①코드에 흔적만 있고 화면이 없는 것 ②실사용자가 걸릴 지점 ③서비스 위에 올리면 좋을 것
> **제안만 정리한 문서다. 구현 지시가 아니다.**

---

## 0. 한 줄 진단

기획→큐시트→저장→진행까지 **한 줄기는 다 이어져 있다.** 지금 비어 있는 건 기능이 아니라 **끝단 두 개** —
"진행이 끝난 뒤"(결과·시상·회고)와 "현장에서 폰이 실제로 버티는가"(화면 꺼짐·타이머·모바일 조작).
차별점으로 잡은 *현장 진행 콘솔*이 정확히 그 두 곳에서 아직 얇다.

---

## 1. 미완 — 코드는 있는데 화면이 없다

| # | 항목 | 현재 상태 | 근거 |
|---|---|---|---|
| A1 | **문제팩 사용자 추가 UI** | `saveItemPack` / `parseItemLines` / `duplicateItemIds` / 카테고리 접두어 검사까지 전부 구현됐는데 **호출하는 화면이 하나도 없다.** 게임 상세는 "직접 추가한 N개 포함" 문구만 출력. `/items`는 `/admin`으로 리다이렉트 | `lib/item-packs.ts`, `lib/item-pack-store.ts` |
| A2 | **아키타입 전용 위젯** | `/play`가 전 게임을 "타이머+문제카드+점수판" 한 벌로 렌더. PICK(룰렛)·BOMB(랜덤 폭발)에 전용 UI 없음 | `app/play/[id]/play-content.tsx` |
| A3 | **진행 결과 화면** | 마지막 게임에서 "진행 마치기" → 곧장 `/cuesheets`. 점수·완료/스킵 기록을 다 갖고 있는데 **보여주는 화면이 없다** | 같은 파일 `finishSession()` |
| A4 | **연말 시상식** | 게임 카드 1개로만 존재(`awards`). 자동 집계(MVP·최다 정답·꼴찌)도, 9:16 공유 카드도 없음 | `data/games.ts` |
| A5 | **조 편성** | 조 *이름*만 입력. 실행계획의 참가자 배정은 미구현인데 화면엔 "구성원 배정은 나중에 추가할 수 있어요"라고 안내 중 | `app/create/page.tsx` |
| A6 | **사운드·진동** | 전무. 타이머가 **무음으로** 끝난다. 진행자가 화면을 안 보고 있으면 종료를 모름 | 전체 |
| A7 | **페이스 관리** | 게임별 타이머만 있고 전체 경과/잔여/오버런 경고 없음. 취약점 문서 S4가 그대로 남아 있음 | `play-content.tsx` |
| A8 | **온보딩** | 없음. 첫 방문자는 홈에서 바로 "게임 찾아보기 / 행사 준비하기" | — |
| A9 | **진행 중 게임 추가** | 스킵·앞뒤 이동만 가능. 시간이 남을 때 즉석 삽입 불가(모달은 `/create/result`에만 있음) | `play-content.tsx` |

### A10. 카탈로그 이원화 — 숫자가 두 개다
- 원본 CSV·seed SQL: **게임 54종 / 문항 1,801개**
- 코드 폴백 `src/data/games.ts`: **20종** (+`game-profiles.ts` 20개)
- `useGameCatalog`는 DB 조회 실패·오프라인이면 조용히 폴백으로 내려간다 → **같은 화면이 54개였다가 20개가 된다.**
- 홈은 아예 서버에서 폴백을 직접 import → 히어로에 **"20개 검증 게임"**이 박혀 나온다. 추천 카드 4개도 id 하드코딩(`balance/choseong/charades/speed-quiz`)이라 게임이 늘어도 홈은 안 변한다.

## 2. 실사용자가 걸릴 지점 (웹)

### 🔴 현장에서 바로 사고가 나는 것

**B1. 폰 화면이 꺼지면 타이머가 죽는다**
Wake Lock 없음 + 타이머가 `setInterval` 1초 누적식(타임스탬프 기준 아님). 진행 중 폰이 잠기거나 브라우저가 백그라운드로 가면 카운트가 밀리거나 멈춘다. 15분 게임을 재보면 안다.
→ 화면 켜둠 유지 + "시작 시각 기준 계산"으로 바꾸는 게 순서.

**B2. 모바일에서 큐시트 순서를 못 바꾼다**
순서 변경이 HTML5 drag(`draggable` + `dragstart`) 하나뿐인데 iOS/안드로이드 터치에서는 동작하지 않는다. 위/아래 버튼 같은 대체 수단도 없다. 폰으로 기획하는 사람은 여기서 막힌다.

**B3. 로그아웃 상태에서 저장한 플랜이 "사라진다"**
저장 시엔 *"이 기기에 저장했어요"*라고 안내하는데, `/cuesheets`는 비로그인일 때 로컬 플랜을 **아예 안 보여주고** 로그인 유도 화면만 띄운다. 사용자 입장에선 저장한 게 날아간 것으로 보인다. (직전 화면의 "지금 진행 시작" 링크로만 들어갈 수 있음)

### 🟠 진행 중 계속 거슬리는 것

| | 증상 |
|---|---|
| B4 | 점수가 **±10 고정**, 취소(undo) 없음. 5점·1점을 못 주고, 잘못 누르면 반대로 눌러 되돌려야 함 |
| B5 | 개인전 점수판이 `참가자 1…N` 자동 생성. 40명이면 **드롭다운에서 사람 찾기**부터 고역, 이름은 전부 수동 입력 |
| B6 | 문항 카드에 "다음 →"만 있음. 이전 카드로 못 돌아가고, **몇 개 중 몇 번째인지도 안 보인다**(90문항 중 어디쯤인지 감이 없음) |
| B7 | 진행 화면에서 **큐시트 전체 목록을 못 본다.** 3번째 게임에서 6번째로 점프 불가(앞뒤 한 칸씩만) |
| B8 | 정답이 진행자 화면에 그대로 노출. 폰만 쓰면 괜찮지만 **빔·TV 미러링하면 정답이 같이 뜬다** |

### 🟡 기획 단계에서 어긋나는 것

| | 증상 |
|---|---|
| B9 | 게임 상세의 **"이 게임으로 행사 준비"가 그 게임을 안 담는다.** `/create` 첫 단계로만 보내서, 조건을 다 고른 뒤 라이브러리에서 그 게임을 다시 찾아 추가해야 함 |
| B10 | 인원 칸을 비우면 `people=0`으로 넘어가 **추천 결과가 0개**가 될 수 있다 |
| B11 | 추천이 완전 결정적. 같은 조건이면 **항상 같은 큐시트**가 나오는데 "다른 조합으로 다시" 버튼이 없다. "매번 새로운 게임" 약속과 정면으로 부딪힘 |
| B12 | 내 게임에 `profile`이 없어서 → 라이브러리에서 **인원 필터를 켜는 순간 내 게임이 전부 사라진다**(`matchesPeople`이 profile 없으면 false). 카드에도 "인원 확인 필요"로 표시. 반대로 추천 엔진에서는 무조건 통과라 기준이 서로 반대 |
| B13 | 내 게임 만들기에서 **문항에 답이 필수.** 밸런스·만약에 같은 제시어형(prompt) 문항을 못 만든다. 진행 멘트도 1단계를 그대로 재사용, 에너지는 3 고정 |
| B14 | 오프라인 캐시가 목록 화면까지만. **게임 상세·문항 페이지는 오프라인에서 안 열린다.** 캐시 목록엔 지금은 리다이렉트인 `/items`가 아직 남아 있음 |
| B15 | 라이브러리 분류가 프로그램·출발점·상황뿐. **게임 유형(퀴즈/토크/서바이벌…) 필터가 없다** — 아이콘으로는 보여주면서 |

## 3. 있으면 좋을 것 — 우리 서비스 위에 올릴 것

### C1. 참가자 화면 분리 (⭐ 가장 크게 벌어지는 차별점)
진행자 폰 = 콘솔(대본·정답·점수), 노트북/빔/TV = 참가자 화면(문제만 크게, 정답 숨김).
같은 브라우저면 `BroadcastChannel`, 다른 기기면 진행 세션 id 공유로 서버 없이도 상당 부분 된다.
→ B8(정답 노출)을 해결하면서 "유튜브·블로그가 못 하는 것"을 눈에 보이게 만든다. 술집 TV 하나만 있어도 그림이 달라짐. 규모: 대

### C2. 진행 결과 리포트 → 시상식 → 공유 카드 (A3+A4 한 줄기)
이미 점수·완료/스킵·문항 소진 기록을 다 들고 있다. 끝나면 자동으로:
- 종합 순위 / 오늘의 MVP / 최다 정답 / 최다 벌칙 / 꼴찌
- 진행자가 즉석 부문 추가("출석왕")
- 9:16 카드 저장 → 단톡방
바이럴 고리이면서 동시에 "참가자 접속 0" 철학을 안 깬다. 규모: 중

### C3. 행사 기록을 다음 행사에 쓰기 (가장 값싼 차별점)
지금은 `gameProgress`(완료/스킵)를 **저장만 하고 아무 데도 안 쓴다.** 이걸 살리면:
- "지난 행사에서 스킵한 게임" 추천 순위 하락
- "이미 쓴 문항 제외" — 세션 *간* 소진. 취약점 C1("두 번째 MT에서 또 이거네")의 진짜 해법
- "지난 행사 그대로 다시" (큐시트 복제)
데이터가 이미 쌓이고 있어서 UI만 붙이면 된다. 규모: 소~중

### C4. 준비물 체크리스트
`profile.preparations`가 이미 게임마다 있다. 큐시트에서 자동 합산해 "오늘 필요한 것: 종이·펜, 점수 기록 도구, 음악 기기" 한 장. 행사 전날 화면. 규모: 소

### C5. 팀 배정기
이름 타이핑 없이 번호 뽑기 / 인원 랜덤 분배 / 홀수 처리. 이름은 선택. (A5와 M2 대응) 규모: 소~중

### C6. 큐시트 공유·인쇄
읽기 전용 공유 링크 + A4 인쇄 뷰. 부진행자·스태프는 폰을 같이 못 보므로 **종이 한 장**이 현실적으로 제일 많이 쓰인다. 규모: 소

### C7. 플레이어 시점 시뮬레이션 ("혼자 해보기")
게임 상세에서 아바타 8명 중 1번 좌석으로 한 판. 끝나면 평균 정답 시간·무응답 문항·예상 소요 → 문제 난이도 조정 근거. 아키타입 단위 규칙으로 짜면 커뮤니티 게임에도 공짜로 붙는다. (별도 결정 문서 있음) 규모: 대 — **C1·C2 뒤**

### C8. 잔가지 (각 반나절 안쪽, 체감은 큼)
- 타이머 종료 비프 + 진동 (A6의 최소판)
- 게임 즐겨찾기 / 최근 사용
- 진행 화면에 큐시트 목록 시트(B7) + 점프
- 문항 진행률 `12 / 90` 표시(B6)
- 점수 커스텀(±1/±5/±10) + 직전 취소(B4)
- 홈 통계를 실제 카탈로그 수로(A10)
- "이 게임 담고 행사 준비"(B9) — `/create`에 게임 id 전달

## 4. 순서 제안

| 순위 | 묶음 | 이유 |
|---|---|---|
| 1 | B1 · B2 · B3 | 현장에서 사고가 나거나 데이터가 사라진 것처럼 보이는 것. 기능 추가보다 먼저 |
| 2 | A10 · B12 · B13 | 숫자와 필터가 서로 안 맞는 상태. 게임을 늘릴수록 손해가 커짐 |
| 3 | A2 (룰렛·폭탄 위젯) · C4 · C8 일부 | 각 반나절, 현장 체감 큼 |
| 4 | C2 (결과→시상→카드) | 실행계획 W8. 바이럴 고리 |
| 5 | C1 (참가자 화면) | 차별점을 가장 크게 벌리는 카드. 시간이 필요하니 알파(W7) 결과 보고 결정 |
| 6 | C3 · C7 | 재방문·리텐션. 공개 이후 |

**알파(W7) 전에 반드시 확인할 것:** 비행기모드에서 켜지는가 / 폰 잠갔다 풀었을 때 타이머와 점수가 살아 있는가 / 폰으로 큐시트 순서를 바꿀 수 있는가.
