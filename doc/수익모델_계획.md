# RecPlus 수익모델 계획 — 이용률 먼저, 수익은 나중에

작성 2026-09-04 · 전제: 11/10 공개 → 11~12월 종강총회 실사용 (실행계획_2026겨울.md)

---

## 0. 결론 세 줄

1. **광고는 "진행 도구"가 아니라 "게임 백과사전"에서 번다.** 한 도메인에 성격이 다른 두 제품을 얹고, 광고는 콘텐츠 면에만 붙인다.
2. **12월 시즌엔 광고를 켜지 않는다.** 켜는 순간 Vercel Pro 비용(월 약 3만원)이 발생하는데, 그걸 회수하려면 월 1.5만 PV가 필요하다. 첫 시즌엔 못 넘는다.
3. **지금 당장 할 일은 광고 코드가 아니라 계측과 SEO 기반공사다.** 특히 게임 상세 페이지가 검색엔진에 빈 페이지로 보이는 상태 — 이걸 고치기 전엔 광고 수익 논의 자체가 성립하지 않는다.

## 1. 지금 코드 상태 진단 (수익화 관점)

Next.js 16.3.3 App Router / React 19 / TS / Tailwind v4, Supabase Auth+DB, PWA. 소스 약 5,400줄.

### 이미 있어서 수익화에 쓸 수 있는 자산

| 자산 | 위치 | 왜 자산인가 |
|---|---|---|
| 공식 게임 19종 (룰 3단계·진행 대본·인원/장소/난이도 메타) | `src/data/games.ts`, `game-profiles.ts` | 검색 유입용 콘텐츠 페이지 19개의 원재료 |
| 게임 라이브러리 필터 (상황·인원·시간·준비물·프로그램) | `/games` | 롱테일 키워드 랜딩 페이지로 확장 가능 |
| 준비물(`profile.preparations`) 필드 | `game-types.ts` | 제휴 링크(쿠팡 파트너스)를 붙일 자연스러운 자리 |
| 게임 CMS + 검수 워크플로 | `/admin`, 마이그레이션 7개 | 콘텐츠를 코드 수정 없이 늘릴 수 있음 = 광고 승인 요건을 채우는 통로 |
| 연말 시상식(`awards` 게임) | `data/games.ts` | 참가자 40명에게 도달하는 **유일한** 대량 노출 접점 |
| PWA + 오프라인 | `manifest.ts`, `public/sw.js` | 현장 신뢰성 = 재방문 = 트래픽의 기반 |

### 수익화를 막고 있는 것 (심각한 순)

**① `/games/[id]`가 검색엔진에 빈 페이지다 — 최우선 블로커**

```
app/games/[id]/page.tsx  →  <GameDetailContent id={id} />   ("use client")
game-detail-content.tsx  →  useGameCatalog() → useEffect에서 Supabase fetch
```

서버가 내려주는 HTML에 게임 이름도, 룰도, 설명도 없다. 게다가 `generateMetadata`가 없어서 게임 19개가 전부 루트 title(`레크플러스 | 5분 만에...`)을 공유한다.
→ 구글 입장에선 **똑같은 제목의 빈 페이지 19개**. 색인이 안 되고, 애드센스 심사에선 "가치가 별로 없는 콘텐츠"로 바로 거절되는 형태다. `/games` 목록도 동일.

**② 계측이 하나도 없다**
GA4도, Vercel Analytics도, 자체 이벤트 로그도 없다(`package.json` 의존성 5개뿐). "이용률을 먼저 높인다"는 전략인데 이용률을 측정할 수단이 없다. 12월 시즌이 끝나고 나서 "잘 됐나?"를 물어봐도 답할 데이터가 없다.

**③ SEO 기본 파일 부재**
`robots.ts` / `sitemap.ts` / `metadataBase` / OG 이미지 전부 없음. 카톡으로 링크 공유해도 썸네일이 안 뜬다 — 11월 공개가 링크 공유 중심인데 치명적.

**④ 광고 붙일 면과 절대 못 붙일 면이 코드에 구분돼 있지 않다**
지금 붙이면 나중에 "여기도 붙일까?"로 계속 흔들린다. 규칙을 먼저 못 박아야 한다(5장).

**⑤ 문제 데이터 36개 (게임당 3개)**
목표 600문항의 6%. `data/game-items.ts` 주석에도 "임시 시드"라고 적혀 있다. 이게 리텐션·광고 승인·유료팩 **세 가지를 동시에** 막는 병목이다.

**⑥ 실행계획과 코드가 어긋나 있음**
9/1에 "Supabase는 12월 MVP에서 제외" 결정 → 실제로는 Auth·RLS·게임 카탈로그·제출 워크플로까지 이미 붙었다. 무료 티어의 **7일 미사용 시 일시정지** 리스크가 그대로 살아 있다. 비수기(1~2월, 여름)에 프로젝트가 멈추면 게임 상세 페이지가 통째로 죽고 → 검색 순위 하락 + 광고 게재 페이지 접근 불가.
→ **SEO 대상 페이지는 Supabase 의존을 끊고 빌드 타임 정적 데이터로 굳혀야 한다.** (아래 액션 2번과 같은 작업)

## 2. 구조적 제약 — 이 제품이 광고로 벌기 어려운 이유

솔직하게 짚고 간다. 이걸 알고 설계해야 헛수고를 안 한다.

1. **사용자 1명 = 모임 1개.** "참가자 접속 0" 철학상 40명 모임에서 접속하는 건 진행자 1명뿐. 트래픽 상한이 구조적으로 낮다.
2. **세션당 페이지뷰가 적다.** 진행자 동선은 `/` → `/games` → 상세 2개 → `/create` → `/create/result` → `/play`. 약 7 PV인데, 그중 가장 오래 머무는 `/play`는 광고를 붙이면 안 되는 화면이다. 광고 가능 PV는 세션당 5회쯤.
3. **계절성이 극심하다.** 3월 새터, 9월 개강, 11~12월 종강총회. 비수기 트래픽은 0에 가깝다.
4. **핵심 화면과 광고가 정면으로 충돌한다.** 이 앱의 가치는 "진행자가 현장에서 안 죽는 것"인데, 어두운 술집에서 진행 중에 광고가 뜨면 제품이 죽는다.

**그래서 결론은 하나다.** 광고 수익은 도구 사용자가 아니라 **검색으로 들어와 읽고 나가는 사람**에게서 나온다.
"MT 게임 추천", "종강총회 게임", "술자리 게임 룰", "몸으로 말해요 제시어" 같은 키워드로 들어오는 트래픽. 이 사람들은 앱을 안 써도 된다. 광고만 보고 나가면 그게 수익이다.

한 도메인에 두 제품:

| | 콘텐츠 축 (광고) | 도구 축 (유료화) |
|---|---|---|
| 라우트 | `/`, `/games`, `/games/[id]`, `/guide/*` | `/create/*`, `/play/*`, `/cuesheets`, `/account` |
| 유입 | 검색·SNS | 링크 공유·재방문 |
| 렌더 | **정적(SSG) 필수** | 클라이언트 OK |
| 수익 | 애드센스 + 제휴 | 시즌팩·팀 라이선스 |
| KPI | 월 PV, 색인된 페이지 수 | 진행 완주율, 재사용률 |

## 3. 숫자 감각 — 얼마나 모아야 얼마 버나

국내 웹 애드센스 페이지 RPM은 대체로 **$1~3 / 1,000PV (약 1,400~4,300원)** 수준이고, 정보성·도구성 주제는 낮은 쪽에 붙는다. 아래는 **RPM 2,000원** 기준.

| 월 PV | 월 광고 수익 | 의미 |
|---|---|---|
| 1만 | 약 2만원 | Vercel Pro 비용도 안 나옴 (적자) |
| **1.5만** | **약 3만원** | **손익분기 (Pro $20/월)** |
| 3만 | 약 6만원 | 운영비 자립 시작 |
| 10만 | 약 20만원 | 용돈 수준 |
| 30만 | 약 60만원 | 여기부터 "수익"이라 부를 만함 |

> ⚠️ **Vercel Hobby는 비상업적·개인 용도 전용이다.** 광고를 다는 순간 약관상 Pro($20/월/seat)로 올라가야 한다. 즉 **광고를 켜는 행위 자체가 월 약 3만원의 고정비를 만든다.**
> 대안: Cloudflare Pages/Workers는 무료 플랜에 상업적 이용 제한이 없다. Phase 2에서 "Pro 결제 vs Cloudflare 이전" 중 하나를 고르면 된다.

**도구 사용자만으로 손익분기를 넘을 수 있나?** 월 1.5만 PV ÷ 세션당 5PV = **월 3,000 진행자**. 첫 시즌 대학 동아리 규모로는 불가능하다.
→ **PV의 80%는 검색 콘텐츠가 만들어야 한다.** 게임 19종 상세 + 가이드 10편이 색인되면 시즌에 월 2~5만 PV는 1년 차 목표로 현실적이다.

### 1년 차 현실적 목표

| 시점 | 수익 | 성격 |
|---|---|---|
| 2026-12 (첫 시즌) | **0원** | 이용률·데이터 확보만 |
| 2027-03 (새터 시즌) | 월 4~10만원 | 운영비 자립 |
| 2027-11 (2년차 종강총회) | 월 20~50만원 | 광고 + 유료팩 |

**이 제품은 단기간에 생활비가 되는 사업이 아니다.** 1년 차 목표를 "운영비 자립 + 실사용 데이터 확보"로 잡아야 계획을 지킬 수 있다.

## 4. 4단계 로드맵 — 각 단계는 게이트를 통과해야 다음으로 간다

### Phase 0 — 기반공사 (지금 ~ 11/10 공개) · 수익 0

목표: **측정할 수 있게 만들고, 검색엔진이 읽을 수 있게 만든다.** 광고 코드는 한 줄도 안 넣는다.

- 계측 심기 (GA4 + Vercel Analytics)
- `/games`, `/games/[id]` 서버 렌더 전환 + `generateStaticParams` + `generateMetadata`
- `robots.ts` / `sitemap.ts` / `metadataBase` / OG 이미지
- `<AdSlot>` 빈 컴포넌트 + 광고 금지 라우트 규칙 문서화
- 연말 시상식 공유 카드에 도메인 워터마크

**게이트 → Phase 1**: 게임 19종이 각자 다른 title/description으로 색인 신청 가능한 상태.

### Phase 1 — 이용률 극대화 (11/10 ~ 2026-12) · 수익 0

목표: **실사용 진행자를 최대한 모으고, 무엇이 작동하는지 데이터로 확인한다.**

- 직접 영업 20팀 (에브리타임·학과 단톡·동아리연합)
- 연말 시상식 9:16 카드 → 참가자 40명 × 20팀 = 800명 노출. **1차 바이럴 엔진**
- 문제 데이터 목표치 달성 (실행계획 6장 파이프라인)
- 매주 지표 확인: 큐시트 생성 수 / `/play` 진입률 / 완주율 / 재사용률

**목표 지표**: 큐시트 생성 300건, 진행 완주 100건, 재사용 진행자 25%
**게이트 → Phase 2**: 완주 50건 이상 + 재사용 20% 이상. 미달이면 광고로 넘어가지 말고 제품을 더 고친다.

### Phase 2 — 검색 트래픽 축적 + 광고 승인 (2027-01 ~ 02) · 수익 0~소액

목표: **애드센스 승인 요건을 채우면서, 그 작업이 곧 제품 개선이 되게 한다.**

애드센스 승인은 대체로 **원본 콘텐츠 10~15개 이상, 글당 1,500자 이상, 개인정보처리방침·소개·문의 페이지, HTTPS, 도메인 2~4주 이상 운영**을 본다. 심사는 1~4주.
→ RecPlus는 `/privacy`, `/terms`, HTTPS는 이미 있다. **부족한 건 "읽을 거리"뿐이다.**

- 게임 상세 19종을 **완전한 진행 가이드**로 승격 (룰 3단계 + 자주 나오는 상황 대처 + 인원별 변형 + 예시 = 1,500자 이상). 이건 취약점 분석의 **C2(진행자 당황 대비)를 해결하는 작업과 동일하다.** 일석이조.
- `/guide` 코너 10편: "MT 레크 진행 완전 가이드", "종강총회 2시간 타임테이블", "40명 조편성하는 법" 등
- **1월 중 애드센스 신청** (3월 새터 트래픽 폭증 직전에 승인 상태를 만들어 둔다)
- 쿠팡 파트너스는 승인 장벽이 없으니 **여기서 먼저 시도**. 준비물 있는 게임 상세에 자연스럽게. 수수료 최대 3%(생활용품 2%), 월 2만원부터 정산, 대가성 문구 표기 필수.

**게이트 → Phase 3**: 애드센스 승인 + 월 PV 2만 돌파(= Pro 비용 회수선 여유 있게 넘김).

### Phase 3 — 광고 온 (2027-03 새터 시즌~) · 월 4~10만원

- 광고는 5장 규칙대로만 배치
- Vercel Pro 결제 **또는** Cloudflare 이전 (이 시점에 결정)
- 카카오 애드핏 병행 검토 — 국내 광고주라 단가 보완이 되지만 **제휴 협의·인증코드가 필요**해 진입장벽이 있다. 애드센스가 먼저.
- 애드센스 정책상 로그인 뒤 화면·광고 클릭 유도는 금지. `/admin`, `/account`는 광고 제외.

### Phase 4 — 유료화 (2027 하반기~) · 6장 참고

**게이트**: 재사용 진행자 30%+ **그리고** 문항 소진율 60%+ (한 팀이 팩의 60% 이상을 실제로 소비). 이 둘이 안 나오면 유료화는 성립하지 않는다.

## 5. 광고 배치 규칙 — 지금 못 박고 나중에 흔들리지 않기

### 광고를 붙이는 면 (콘텐츠 축)

| 라우트 | 배치 | 개수 |
|---|---|---|
| `/` | 첫 화면 아래, 섹션 사이 | 1 |
| `/games` | 카드 그리드 사이 (12개마다 1개) | 최대 2 |
| `/games/[id]` | 룰 설명 아래 + 관련 게임 위 | 2 |
| `/guide/*` | 본문 중간 + 하단 | 2 |

### 광고를 절대 붙이지 않는 면 (도구 축)

| 라우트 | 이유 |
|---|---|
| `/play/[id]` | **현장 진행 중. 여기 광고 = 제품 사망.** 예외 없음 |
| `/create`, `/create/result` | 결과를 받는 순간이 제품의 클라이맥스. 광고로 끊으면 이탈 |
| `/cuesheets`, `/account`, `/admin` | 로그인 뒤 화면. 애드센스 정책상으로도 부적절 |
| `/offline` | 오프라인이라 광고 로드 자체가 실패 |

### 구현 규칙

- 모든 광고는 `<AdSlot slot="..." />` 하나만 거쳐 렌더한다. 페이지에 스크립트를 직접 심지 않는다.
- `AdSlot`은 허용 라우트 화이트리스트를 내부에 갖고, 그 외에서는 아무것도 렌더하지 않는다.
- 광고 영역은 **고정 높이를 미리 잡는다** (레이아웃 시프트 = 이탈 + Core Web Vitals 하락).
- 광고 스크립트는 `next/script`의 `lazyOnload`. `/play` 진입 시엔 아예 로드하지 않는다.
- PWA 캐시(`sw.js`)에 광고 스크립트를 절대 넣지 않는다.

## 6. 유료화 설계 — 뭘 파는가

**게임 자체를 유료화하지 않는다.** 게임 룰은 유튜브에도 널린 공개 정보라 지불 근거가 약하고, 무료 축이 무너지면 검색 트래픽(=광고 수익)이 같이 죽는다.

지불 의사는 **"두 번째 행사에서 문제가 고갈되는 순간"**에 생긴다(취약점 C1). 그래서 파는 건 **문제와 운영 편의**다.

| 우선순위 | 상품 | 가격 | 근거 |
|---|---|---|---|
| 1 | **시즌 문제팩** (예: "2027 봄 새터팩" 300문항) | 3,900원 | 고갈이 곧 지불 동기. 팀원이 스프레드시트로 만드는 것이 그대로 상품이 됨 |
| 2 | **진행 콘솔 Pro** (큐시트 PDF/PPT 내보내기, 결과 아카이브, 조편성 제약, 다중 진행자) | 시즌권 9,900원 | 학생 대상이라 구독보다 단건·시즌권 |
| 3 | **학과·동아리 팀 라이선스** (연간, 계정 5개 + 전체 팩) | 3~5만원 | **개인 학생 지갑보다 학생회 예산이 훨씬 열려 있다.** 실질적으로 여기가 제일 크다 |

절대 유료화하지 않는 것: 게임 룰 · 기본 문제 풀 · `/play` 진행 기능 자체 · 큐시트 자동생성.

결제는 토스페이먼츠 또는 포트원. **사업자등록이 필요하므로 Phase 4는 "사업을 할 것인가"를 실제로 결정하는 시점이다.** 그 전까지는 결제 코드를 쓰지 않는다.
