## 2. 먼저 정리할 결정 4가지

### 결정 1 — 종강총회는 새터가 아니다. 제품도 달라져야 한다

| | 3월 새터 | 11~12월 종강총회 |
|---|---|---|
| 관계 | 처음 보는 사이 | 이미 아는 사이 |
| 목적 | 어색함 깨기 | 한 해 마무리·회고 |
| 장소 | 펜션·대형 홀 | 술집·과방·실내 소규모 |
| 시간 | 1박 2일 | 2~3시간 |
| 인원 | 40~100명 | 15~40명 |

**영향**
- phase 비율 조정: 아이스브레이킹 28% → **15%**, 토크·메인 확대 (오프닝 10 / 아이스 15 / 메인 55 / 피날레 20)
- `place`는 `room` 최적화가 1순위. `hall`(대강당)은 후순위로 미룸
- **랜덤 플레이 댄스가 술집에선 안 돌아간다.** 브리프가 지목한 "피날레 겸 바이럴 엔진"이 이번 시즌엔 공백 → 대체 필요
- "올해의 순간" 시즌 문제팩이 최신성의 핵심 장치

**신규 제안: 연말 시상식 (Awards) — 이번 시즌의 피날레 겸 바이럴 엔진**
진행 중 쌓인 데이터(점수·정답 수·벌칙 횟수·생존)로 시상을 자동 생성하고 9:16 카드로 뽑는다.
- 자동 부문: 종합우승 / 오늘의 MVP / 최다 벌칙 / 최다 정답 / 꼴찌상
- 수동 부문: 진행자가 즉석에서 부문명 입력 + 사람 지정 (예: "출석왕")
- 브리프 S2가 지적한 "MVP 하드코딩" 문제를 근본적으로 해결하는 기능이기도 함
- 새터에도 그대로 쓰인다. 시즌 한정 기능이 아님

### 결정 2 — 차별점은 "현장 진행 콘솔" 하나로 뾰족하게
브리프 B1의 미해결 과제. 3개월로는 커뮤니티 해자를 못 만든다. 셋 중 하나만 고른다.
- 검증된 순서(추천엔진) → 블로그·유튜브가 흉내 가능
- 커뮤니티 게임 → 유저가 없으면 빈 껍데기 (닭-달걀)
- **현장 진행 콘솔 → 유튜브·블로그가 절대 못 하는 것.** 시간·점수·룰·사운드가 한 화면에서 살아 움직이는 것

→ **12월까지 개발 시간의 40%를 진행 콘솔에.** 나머지 기능은 "충분히 작동"만 하면 된다.

### 결정 3 — 디자인: 문서 두 개가 충돌 중이니 용도로 나눈다
브리프 7항은 Apple 라이트, 추천로직 설계서 2-1은 다크 네온. 둘 다 맞고, 쓰이는 맥락이 다르다.

| 맥락 | 테마 | 근거 |
|---|---|---|
| 데스크톱 기획·빌더·검수 | **라이트** `#F5F5F7` | 오래 보는 작업 화면, 신뢰감 |
| 모바일 현장 진행 | **다크 기본** `#0A0A0F` | 어두운 현장 눈부심, 타격감 |

CSS 변수 토큰 한 세트로 스위칭. 토글은 남기되 `/play` 라우트의 기본값은 다크.

### 결정 4 — Supabase는 12월엔 붙이지 않는다 (2027년 1월로)
- 로그인·커뮤니티는 이번 시나리오에 불필요 ("참가자 접속 0" + 진행자 혼자)
- 무료 티어 **7일 미사용 시 일시정지** → 12월 이후 비수기에 그대로 리스크
- 문제팩 갱신은 정적 JSON 배포(Vercel)로 충분하다

→ **12월 구성: 유저 데이터 = localStorage / 콘텐츠 = `/public/data/*.json` fetch + 캐시**
→ 2027년 1월(3월 새터 준비)에 Supabase + 로그인 + 커뮤니티 착수

## 5. 기술 스택 (확정)

| 영역 | 선택 | 이유 |
|---|---|---|
| 프레임워크 | **Next.js 16 App Router + TypeScript** | 브리프 확정안 |
| 스타일 | **Tailwind CSS v4** + CSS 변수 토큰 | 라이트/다크 스위칭을 토큰 하나로 |
| 상태 | **Zustand** + persist(localStorage) | 가볍고, 진행 중 상태 복구에 적합 |
| PWA | **Serwist** | `next-pwa`는 유지보수 중단됨 |
| 사운드 | **Howler.js** + 로열티프리 mp3 | 오프라인 보장 (번들 내장) |
| 공유 카드 | **html-to-image** → PNG → Web Share API | 서버 렌더 불필요 |
| 배포 | **Vercel** (Hobby 무료) | GitHub push → 자동 배포 |
| 저장소 | **GitHub private** | 팀 협업·이력 |
| 폰트 | **Pretendard** 셀프호스팅(`next/font/local`) | CDN 의존 시 오프라인에서 깨짐 |
| 테스트 | Vitest(엔진만) + Playwright 스모크 1개 | 최소한만 |

### 폴더 구조 (제안)
```
recplus/
  src/
    app/
      (desktop)/          # 기획: 대시보드 · 큐시트 빌더 · 게임 빌더  (라이트)
      play/               # 현장 진행                                (다크)
    engine/               # ★프레임워크 무관 순수 로직
      archetypes/         # QUIZ TALK SURVIVAL PERFORM PICK BOMB
      recommend.ts        # 3층 추천 (필터 → 흐름 배치 → 최신성)
      pool.ts             # 랜덤 소진 (한 세션 내 재출제 금지)
      score.ts            # 개인/팀 점수 + 시상 집계
    components/
    store/
  public/
    data/
      games.json          # 게임 메타
      items/<gameId>.json # 문제 풀 — 게임별 분리 = 필요한 것만 로드
      packs/2026-winter.json
  content/                # 원본 CSV (팀원 산출물)
  scripts/build-content.ts
```
`engine/`을 UI에서 분리해두는 게 핵심이다. 브리프 5항의 "게임 엔진 별도 패키지 분리"를 처음부터 지켜두면 테스트도 쉽고, 나중에 네이티브로 옮길 때 이 폴더만 들고 간다.

## 6. 콘텐츠 파이프라인 — 팀원이 코드 없이 참여하는 법

```
Google 스프레드시트 (팀원 작업)
   ↓ CSV 내보내기 → content/ 에 저장
   ↓ pnpm content:build   (자동 검사 + 변환)
   ↓ public/data/*.json
   ↓ git push → Vercel 자동 배포
```
**팀원은 스프레드시트만 만진다.** 돈희가 주 1회 빌드 + 배포.

### 시트 컬럼 (유형별 3종류면 충분)
- **QUIZ**: `game_id | category | question | answer | hint | difficulty | tags | status`
- **TALK**: `game_id | question | option_a | option_b | tags | season | status`
- **PERFORM / PICK**: `game_id | word | level | tags | status`

`status` = `draft`(작성중) / `review`(검수요청) / `ready`(투입). **`ready`만 빌드에 포함된다.**

### 빌드 스크립트가 자동으로 잡을 것 (브리프 M3의 저비용 실행판)
- 게임별 개수가 30개 미만 → 경고
- 정규화 후 중복 (공백·괄호·조사 제거 후 비교)
- 금칙어 목록 히트
- 정답 누락, 카테고리 접두어 형식 위반 (`[음식] ㄸㅂㅇ`)
- 결과를 `content/report.md`로 출력 → 팀에 그대로 공유

### 목표 수량 (총 ~600문항)
| 등급 | 게임 | 목표 |
|---|---|---|
| 1급 (매 세션 등장) | 초성퀴즈 100 · 스피드퀴즈 80 · 밸런스 60 · 몸으로말해요 60 · 만약에 50 | **350** |
| 2급 | 이어말하기 40 · 인물퀴즈 40 · 벌칙 40 · 이심전심 30 · 손병호 30 | **180** |
| 3급 (룰 위주) | 청개구리 20 · 눈치 / 369 / 시한폭탄 각 10~15 | **~60** |
| 시즌팩 | "2026 회고" (밸런스·만약에·N행시 혼합) | **60** |

주당 약 50문항 × 12주. **2명이 나누면 1인당 주 25개 = 하루 4개.** 이건 지킬 수 있는 페이스다.

### 작성 규칙 (브리프 3항 준수)
- 방송 문제를 그대로 옮기지 않는다. 포맷만 참고
- 실명 연예인 → 텍스트 힌트형으로 우회
- 브랜드·로고 → 일반 사물·음식으로 대체
- 카테고리 접두어 형식 고정 → 파싱해서 필터·통계에 사용

## 7. 검증 계획

### W7 알파 — 직접 진행 (10~15명)
체크리스트: 앱 안 보고도 진행 가능한가 / 룰 설명이 실제로 통하는가 / **비행기모드에서 켜지는가** / 진행 중 폰 껐다 켜기 / 배터리 소모 / 예측 시간 vs 실제 시간

### W10 베타 — 5~10팀 (지인 진행자)
- 배포: 링크 + 설치 안내 1장
- 수집: 완주율 / 중도 이탈 지점 / 스킵된 게임 / "다음에 또 쓸 건가" 1문항
- 계측: 어떤 게임이 실제로 쓰였는지 (localStorage 집계 → 수동 회수)

### 자동 테스트는 최소로
- 추천엔진: 인원·장소·시간 조합 20개를 넣어 항상 유효한 큐시트가 나오는지
- 랜덤 소진: 같은 세션에서 중복 출제가 안 되는지
- 나머지는 손으로 확인한다
