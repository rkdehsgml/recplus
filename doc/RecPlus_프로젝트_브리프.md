# RecPlus (레크마스터) — 프로젝트 브리프

> MT·새터 레크리에이션 진행자를 위한 웹 서비스.
> 이 문서는 지금까지 확정된 결정사항과 그 **근거**를 담는다. 새 대화에서 이 문서만 읽으면 맥락이 이어진다.
> 최종 갱신: 2026년 9월

---

## 1. 서비스 정의

**한 줄:** 레크를 떠맡은 사람이 검색·정리에 쓰던 3시간을 5분으로 줄이고, 검증된 순서의 큐시트를 받아 현장에선 폰만 보고 진행하게 만든다.

**절대 원칙 (흔들면 안 되는 것)**
- **참가자는 앱을 설치하거나 접속하지 않는다.** 진행자 한 명만 쓴다. 이게 최대 차별점이자 개발 난이도를 크게 낮추는 결정.
- **서버 없이도 핵심이 돌아간다.** 로컬 완결 구조. 커뮤니티 기능을 열 때만 백엔드가 필요.
- **검증된 게임만 넣는다.** 양보다 "실제로 터지는 것".

**타겟 (우선순위 순)**
1. 과 학생회 · 동아리 총무·기획부장 — 하고 싶어서가 아니라 **직책 때문에 떠맡은** 사람. 진짜 고통은 "40명 앞에서 혼자 진행해야 하는데 어색해지면 내 탓이 됨". 이 앱은 재미 도구가 아니라 **진행 실패 공포를 없애는 보험**.
2. 회사 워크샵·회식 진행을 맡은 막내/총무 — 시즌을 안 타서 비수기를 메움.

**시즌 전략**
- 폭발 시점: 3월 초(새터·OT), 9월 초(개강총회). 축제(5월/9월), 연말 종강총회가 보조.
- **시즌 앱의 저주**: 3월 반짝 → 4월 사망 → 9월 처음부터. 이걸 깨는 장치가 리텐션의 핵심.
- 저주를 깨는 3가지: ①매번 다른 문제(랜덤 소진) ②저장된 큐시트 재사용 ③직장 워크샵 상시 수요.
- 출시는 시즌 **1~2개월 전** 역산 필요(앱스토어/검색 인덱싱 시간).

**확산 메커니즘**: 주변 입소문 + 인스타 스토리 공유. 참가자가 앱을 안 만지므로 **결과 공유 카드(9:16)가 유일한 바이럴 접점**. 랜덤플레이댄스 영상 공유가 가장 강한 고리.

## 2. 게임 시스템 — 이 서비스의 핵심 자산

### 2-1. 게임 선별 기준 (중요)

51개를 모은 뒤 두 기준으로 냉정하게 걸러냈다:
1. **방송 검증**: 신서유기·지구오락실에서 반복적으로 나오고 항상 터졌는가
2. **현장 실현성**: 진행자 혼자, 준비물 없이, 폰 하나로 굴릴 수 있는가

**제외한 대표 사례와 이유** (같은 실수 반복 방지)
- **고요 속의 외침** → 노이즈캔슬링 헤드폰이 인원수만큼 필요. "방송이라 됐지 현실엔 안 되는 것"의 대표
- **코드네임/한 단어 스파이 등 두뇌게임** → 정적이고 지루함. 레크엔 순발력·몸·토크가 답
- **리듬 술래(딸기/두부), 뻔데기** → 룰이 복잡해 초보 진행자가 못 굴림
- **현미경 퀴즈, 인트로 맞히기** → 이미지·음원 제작 부담 + 저작권 지뢰

**핵심 교훈: 태그(phase/place/mode)가 맞아도 현실 적합은 별개다.**

### 2-2. MVP 게임 15종 (전부 검증 통과)

| 구간 | 게임 |
|---|---|
| 오프닝 | 청개구리 가위바위보(지락실) · 눈치 게임 · 369 |
| 아이스브레이킹 | 밸런스 게임 · 이어 말하기(신서유기) · 만약에 · 손병호 |
| 메인 | 카테고리 초성 퀴즈(지락실 시그니처) · 인물 퀴즈(신서유기) · 몸으로 말해요 · 스피드 퀴즈 · 이심전심 |
| 피날레 | 랜덤 플레이 댄스(지락실, 바이럴 엔진) · 벌칙 룰렛 · 시한폭탄 |

### 2-3. 게임 문법 — 6개 유형 시스템 (설계의 뼈대)

모든 레크 게임은 4개 원자 부품(**점수 / 타이머 / 콘텐츠풀 / 진행방식**)의 조합으로 환원된다.
유저는 부품을 직접 다루지 않고 **유형만 고르면 규칙이 자동으로 붙는다**.

| 유형 | 부품 | 예시 |
|---|---|---|
| 🧠 QUIZ 퀴즈형 | 콘텐츠풀(Q&A) + 점수 + 타이머 | 초성퀴즈, 인물퀴즈 |
| 💬 TALK 토크형 | 질문풀 | 밸런스, 만약에 |
| ⚡ SURVIVAL 서바이벌형 | 생존/탈락 + 타이머 | 눈치게임, 손병호 |
| 🎭 PERFORM 퍼포먼스형 | 타이머 + 점수 + 제시어 | 몸으로말해요, 랜덤댄스 |
| 🎰 PICK 룰렛/추첨형 | 항목풀 + 랜덤추출 | 벌칙룰렛 |
| 💣 BOMB 폭탄/긴장형 | 랜덤타이머 + 릴레이 | 시한폭탄 |

**이 6개로 게임의 95%가 커버된다.** 유저는 "규칙"을 만들지 않고 "유형을 고르고 콘텐츠를 채운다".

### 2-4. 정답의 성격 구분 (자주 헷갈리는 부분)

게임마다 정답의 성격이 달라서 진행 화면 렌더링이 다르다:

| 유형 | 정답 처리 |
|---|---|
| QUIZ | 정답 유일 → **MC에게 정답 상시 표시** + "참가자에게 공개" 버튼 별도 |
| PERFORM | 제시어 자체가 답 → **"🙈 MC만 보세요"** 경고와 함께 표시 |
| category형(이어말하기) | 정답 무한 → **정답 표시 안 함**, 주제만. 참고 예시만 제공 |
| TALK | 정답 없음 → 질문만 |

> "2호선 지하철역"처럼 답이 너무 많은 건 퀴즈로 내면 안 됨 → 토크형으로. 게임 빌더에서 이 안내를 노출 중.

### 2-5. 콘텐츠 운영 원칙
- 게임당 **최소 8개, 권장 30개 이상**. 적으면 "또 이거네"로 리텐션 사망
- **랜덤 소진 방식**: 한 세션에서 본 문제는 재출제 안 됨. 한 바퀴 돌면 재셔플
- 카테고리는 `[음식] ㄸㅂㅇ` 형태로 접두어 저장 → 파싱해서 필터/통계에 사용
- **트렌드 문제팩**을 주기적으로 갱신하는 게 "최신 느낌"의 실체 (서버 없이 JSON 교체로 가능)

## 3. 저작권 · 안전 가이드

- 예능의 **포맷(규칙)은 참고**하되, 문제·단어·질문 **데이터는 전부 오리지널**로 작성
- 방송 고유명(삼장법사, 드래곤볼 등)은 **자체 네이밍으로 치환**
- 연예인 사진 → 초상권 이슈. **텍스트 힌트형**으로 우회
- 브랜드 로고 → 상표권. **일반 사물/음식**으로 대체
- 음원 → 절대 서버에 저장·재호스팅 금지. **공식 플레이어로 재생만**
- 왕게임·진실게임 등은 **순한맛 미션만**. 수위 슬라이더 고려

## 4. 음악 연동 (조사 완료, 구현 예정)

**결론: YouTube IFrame API가 메인 엔진.**

| 방식 | 판정 |
|---|---|
| **YouTube IFrame API** | ⭐ 1순위. 무료·무승인·전곡·안무영상. 로그인 불필요. 단 플레이어가 화면에 보여야 함(최소 200×200) → 대강당 화면에 띄우면 오히려 자연스러움 |
| **Apple MusicKit JS** | 2순위. 전곡 재생 가능하나 **구독자만**, 전곡재생 강제. 진행자 기기 하나만 재생하는 용도 |
| **Spotify** | ✖ 2024.11 신규앱 30초 미리듣기 폐지, 2025.5부터 월 25만 MAU 필요. 사실상 차단 |
| **멜론·지니·유튜브뮤직** | ✖ 공개 재생 API 자체가 없음 |
| **내장 사운드** | 필수. 사운드보드·카운트다운은 로열티프리/자체제작으로 **오프라인 보장** |

**3층 구조**: 내장 사운드(항상) → YouTube(메인) → Apple Music(옵션)

## 5. 기술 스택 (확정)

**웹으로만 개발한다.** iOS 네이티브는 보류 — 웹+PWA로 충분하고, 실사용자 확보 후 판단.

```
프론트: Next.js + TypeScript (Vercel 배포)
백엔드: Supabase (PostgreSQL + Auth + Storage)
현재:   단일 HTML + 바닐라 JS 프로토타입, localStorage
```

**Supabase를 고른 이유**
- 데이터가 관계형(게임↔문제↔큐시트↔세션)이라 Firestore보다 Postgres가 맞음
- Firebase는 2026.2에 Cloud Storage가 무료 요금제에서 제외됨
- 인증·DB·스토리지가 한 번에 → 혼자 개발할 때 통합 작업 수 주 절약
- 구글/카카오 소셜 로그인 기본 지원. RLS로 "본인 큐시트만 접근"을 DB 레벨에서 강제
- ⚠️ 주의: 무료 티어는 **7일 미사용 시 일시정지** → 시즌 비수기에 영향

**DB 스키마 핵심**
- `games` — 게임 틀 + 메타(archetype, phase, energy, place[], mode, duration). `status`로 검수 파이프라인(draft→pending→approved)
- `game_items` — 문제 풀. `approved` 플래그로 **문제 단위 검수** 가능
- `cuesheets` / `cuesheet_games` — 큐시트와 순서
- `play_sessions` / `teams` — 진행 기록. **"지금 뜨는 게임" 추천의 근거 데이터**

**이행 순서**: ①HTML→Next.js 이전하며 게임 엔진을 별도 패키지로 분리 → ②Supabase 붙여 로그인·커뮤니티 → ③(선택) 앱

**개발 환경 (M1 8GB 기준)**
- pnpm 사용(디스크 절약), `next dev --turbo`
- **Docker 쓰지 말 것** — Supabase 로컬 개발은 무겁다. 클라우드에 직접 연결
- 개발 미리보기는 Safari(Chrome은 램 과다)

## 6. 추천 엔진 (큐시트 자동 생성)

**3층 구조**
1. **규칙 필터** — 장소·인원·모드로 가능한 게임만 남김
2. **흐름 배치** — phase 비율로 시간 슬롯 배분 후 energy 낮→높 순으로 채움
   - 비율: 오프닝 12% / 아이스브레이킹 28% / 메인 45% / 피날레 15%
3. **최신성 레이어** — 시즌 태그, 트렌드 문제팩, "지금 뜨는 게임"

**핵심 차별점**: 게임 목록이 아니라 **"왜 이 순서인지" 근거를 보여주는 것**. energy 곡선 시각화 + 게임마다 추천 이유 한 줄. 경쟁 블로그/유튜브엔 없는 것.

## 7. UI/UX 방향

**디자인 언어: Apple 스타일 라이트 테마**
```
배경 #F5F5F7 · 카드 #FFFFFF · 텍스트 #1D1D1F
액센트: 시스템 블루 #0071E3 단일
그라데이션: #0071E3 → #42A5F5 → #5AC8FA (+ 퍼플 #6C5CE7 변형)
알약형 버튼(border-radius:980px) · 부드러운 그림자 · cubic-bezier(.16,1,.3,1)
폰트: Pretendard
```

**크로스 디바이스**
- 데스크톱 = 구성·창작·검수 (큐시트 빌더, 게임 만들기, 관리 콘솔)
- 모바일 = 현장 진행 (대시보드, 사운드보드, 점수판)
- 추출 = PPT(대형화면) · PDF(큐시트) · QR(모바일 전송)

**현장 UX 원칙**
- 조작 버튼은 하단(엄지존)에 집중
- 진행 화면 글씨는 크게. 다크모드 토글 제공(어두운 MT 현장)
- 2탭 안에 모든 게 끝나야 함

## 8. 구현된 화면 (프로토타입)

**서비스**: 랜딩(3종 변형) / 온보딩 / 대시보드 / 큐시트 빌더 / 게임 라이브러리 / 게임 상세 / 게임 만들기 / 커뮤니티 / 내 활동 / 설정 / 모바일 진행 전체 흐름 / 결과 공유

**관리자**: 관리 콘솔(대시보드·게임관리·문제관리·검수·통계·설정) / 문제 관리 최적화 버전

**작동하는 핵심 기능**
- 큐시트 자동 생성(3층 로직), 드래그 순서변경, 목표시간 자동배분 + 실시간 게이지
- 조 편성(2~6조, 이름/번호 랜덤 배정, 재섞기), 유동 점수판
- 진행 중 게임 건너뛰기, 전체 진행바, 타이머 초과 경고
- localStorage 영속화 + **진행 중 상태 복구**(폰 꺼져도 점수 유지)
- 게임 빌더(6유형), 대량 붙여넣기 파싱, 실시간 검증, 진행화면 미리보기
- 검수 파이프라인(제안→승인→라이브러리 등록)
- 문제 관리: 인라인 편집, 카테고리 구조화, 정규화 중복탐지, 일괄 이동/분류/삭제, CSV 내보내기

## 9. 남은 과제 (우선순위)

**🔴 치명적**
- **오프라인 대응(PWA)** — MT 장소는 와이파이가 약하다. 현장에서 안 켜지면 끝
- **콘텐츠 확충** — 게임당 30개+ 목표. 현재 일부만 확보
- **룰 설명 강화** — 각 게임에 "이렇게 진행하세요" 단계별 가이드 (게임 상세엔 있으나 진행 화면엔 부족)

**🟠 심각**
- 개인전 점수판 부재(팀전만 있음)
- 진행 중 게임 추가(스킵만 가능)
- PPT/PDF/QR 실제 생성 (현재 버튼만)

**🔵 전략 (별도 논의 필요)**
- **차별점을 뭘로 뾰족하게 할 것인가** — "유튜브에 MT 게임 100선 치면 다 나오는데 왜 이 앱인가"에 대한 답이 아직 약함. 후보: 검증된 순서 / 현장 콘솔 / 커뮤니티
- **수익 모델** — 무료 + 시즌 게임팩 인앱결제 구조 검토 중, 미확정

## 10. 커뮤니티 선순환 (서비스의 해자)

```
유저가 유형 선택 → 콘텐츠 입력 → 자동 검증 → "커뮤니티에 추천?"
  → 검수 대기열 → 개발자 승인/반려 → 정식 게임 등록
  → 원작자 크레딧과 함께 다른 사람 큐시트에 등장 → 응용/파생
```

**동력**: 크레딧 표시, 인기 지표(명예의 전당), 변형 제안, 시즌 챌린지 공모
**의미**: 게임을 우리가 다 만들지 않아도 콘텐츠가 스스로 자란다. 네트워크 효과 + 락인.
