# 레크플러스 1차 제한 파일럿 — 운영·보유·동의 정책 초안

> 작성: 2026-09-11
> 범위: P02 준비 문서
> 상태: 운영·제품·법률 검토 전. 빈 값을 임의 보유기간이나 SQL 기본값으로 바꾸지 않는다.

## 1. 파일럿 운영 범위

- 참여자는 사전 연락과 피드백이 가능한 **성인 대학 행사 운영자 5–10팀**으로 제한한다.
- SMTP와 소셜 로그인 확대는 이번 파일럿 범위에서 제외한다. 사전 준비된 계정만 사용한다.
- 학교·회사·사적 모임용 데이터 축은 지원하지만 첫 모집·성공 지표에는 포함하지 않는다.
- 조직명, 참가자 실명·연락처, 정확한 행사 일시, 사진·영상은 수집하지 않는다. 참가자 자유입력 이름은 서버 전송하지 않는다.
- 일반 공개 가입을 UI 숨김만으로 막지 않는다. Auth 설정과 서버 쓰기 권한에서 참여 제한을 확인한다.

## 2. 보유·삭제 결정표

다음 수치와 책임자는 **P06 migration 전에** 운영 담당자가 확정한다. `미정`은 보존 또는 삭제를 뜻하지 않는다.

| 데이터 | 최소 목적 | 보유기간 | 삭제 기산점 | 탈퇴 시 처리 | 백업 반영 | 담당 | 상태 |
|---|---|---|---|---|---|---|---|
| 행사 실행·스냅샷·이벤트 | 복구·후기 자격·무결성 | 미정 | 미정 | 미정 | 미정 | 운영 | D04 미정 |
| 로컬 outbox·복구 상태 | 재전송·현장 복구 | 미정 | 미정 | 기기별 삭제/격리 규칙 미정 | 해당 없음 | 개발 | D04 미정 |
| 비공개 후기 | 작성자 보관·공개 제출 준비 | 미정 | 미정 | 미정 | 미정 | 운영 | D04 미정 |
| 공개 후기·동의 증거 | 공개·철회·검수 재현 | 미정 | 미정 | 철회/익명화 규칙 미정 | 미정 | 운영·법률 | D04 미정 |

| 검수·감사 이력 | 권한·결정 재구성 | 미정 | 미정 | 미정 | 미정 | 운영 | D04/D09 미정 |

삭제/철회 처리 순서는 최소한 다음을 만족해야 한다: 새 공개 제출을 먼저 막고, 공개 상태와 보유 대상별 처리 결과를 확인하고, 필요한 감사·동의 증거의 보유 근거를 적용한 뒤, 계정 삭제를 실행한다. 실패나 재시도 중 일부 공개 콘텐츠가 남지 않아야 한다. 백업 복원 뒤에도 삭제 대상 재적용 절차가 있어야 한다.

## 3. 공개 동의와 콘텐츠 처리

후기의 공개 동의는 가입 약관/개인정보 동의와 분리한다. 공개 제출 시점에 다음 증거를 고정한다.

- 동의 문서 ID와 버전, 동의 시각
- 제출한 후기 revision과 본문 해시
- 공개 가능한 크레딧 표시값과 행사 조건 필드
- 작성자·실행·완료 게임 버전의 서버 자격 검사 결과

동의 문안, 콘텐츠 이용허락 범위, 별칭/크레딧 정책, 철회 뒤 처리, 수정·재제출 시 재동의 여부는 담당자 확정 전 공개 migration에 넣지 않는다. published 수정, 작성자 철회, 관리자 긴급 숨김은 즉시 공개 응답에서 제외한다. 복구는 최신 동의·자격·revision·숨김 사유 해결을 다시 확인하고 자동 재공개하지 않는다.

## 4. 역할과 연락 경로

| 역할 | 해야 할 일 | 지정된 담당/연락 경로 | 상태 |
|---|---|---|---|
| 파일럿 운영자 | 계정 배포·회수, 주 기기 안내, 진행/복구 접수 | 미정 | D09 미정 |
| 콘텐츠 검수자 | 후기·제안 검수, 수정 요청/승인/반려 사유 기록 | 미정 | D09 미정 |
| 신고 처리자 | 신고 확인, 처리 결과 통지, 긴급 숨김 판단 | 미정 | D09 미정 |
| 제한 지원 열람자 | 필요한 비공개 원본 열람 시 사유·감사 남김 | 미정 | D09 미정 |
| DB 운영자 | 백업·복구·스테이징 적용·롤백 | 미정 | P00 미확보 |

일반 검수자는 개인 실행 전체와 신고자 신원을 기본 조회할 수 없어야 한다. 제한 지원 열람은 별도 권한, 지원 사유, 작업자·시각 감사 기록을 요구한다.

## 5. 파일럿 접근·계정 운영

1. 참여자별로 별도 계정을 준비하고 U1/U2/A1/A2는 같은 사용자를 역할만 바꾼 테스트로 대체하지 않는다.
2. 계정 배포 시 주 기기 하나, 오프라인 준비 완료, 로그아웃 전 동기화 확인, 기기 분실 시 지원 한계를 안내한다.
3. 로그인/로그아웃과 계정 전환 때 로컬 캐시·메모리·진행 요청·sync worker를 계정 단위로 무효화한다.
4. 일반 공개 가입 제한은 Supabase Auth 설정과 파일럿 쓰기 경로에서 검증한다. SMTP/소셜 공급자 설정은 이 단계에서 열지 않는다.
5. 참여 종료·계정 회수·탈퇴 요청의 접수 창구와 처리 목표 시간은 운영 담당자가 정한다.

## 6. 운영 사건 처리 초안

| 사건 | 즉시 조치 | 보존할 증거 | 후속 결정 |
|---|---|---|---|
| 동기화 충돌/주 기기 불일치 | 해당 run outbox를 멈추고 최신 서버 영수증 확인 | run ID, request ID, 오류 코드, 시각 | 복구 가능 여부·지원 절차 |
| 공개 후기 신고 | 자동 숨김하지 않고 신고 접수 상태 기록 | 신고 대상, 사유, 처리자/시각 | 긴급 숨김 여부·처리 결과 |
| 개인정보/권리 우려 | 신규 공개를 중지하고 즉시 비공개 전환 검토 | revision, 동의, 검수·숨김 사유 | 삭제/보유/이의제기 |
| 계정 탈퇴 | 공개 철회·보유 정책 적용 전 계정 삭제 금지 | 처리 단계·결과 | 재시도/백업 재적용 |
| 백업 복구 필요 | 새 쓰기·공개 제출을 중지하고 원본/outbox 보존 | 복구 시점·대상·대조 결과 | 복구 후 삭제 정책 재적용 |

## 8. P02 완료 기준

P02는 위 표의 수치·담당·연락 경로가 모두 채워지고, 공개 동의와 삭제 정책이 법적 검토를 거쳐 확정되며, P00의 스테이징·복구·계정 증거가 연결될 때만 완료다. 이 초안 작성은 완료를 뜻하지 않는다.
