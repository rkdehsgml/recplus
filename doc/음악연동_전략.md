# 음악 연동 전략 — 레크마스터
## 실제 음원을 합법적으로 게임에 쓰는 법

> 랜덤플레이댄스·노래 전주 퀴즈 등 음악 레크 게임은 앱의 핵심 재미.
> 하지만 음악은 저작권·API 제약이 가장 까다로운 영역이다. 각 서비스의 **현재(2026) 정책**을 확인하고 실전 전략을 정리했다.

---

## 결론 먼저 (TL;DR)

| 방식 | 실제 음원 | 신규앱 가능 | 우리 앱 적합도 | 핵심 제약 |
|---|---|---|---|---|
| **YouTube IFrame API** | ✅ 전곡 | ✅ 가능 | ⭐⭐⭐⭐⭐ **1순위** | 플레이어 화면 노출 필수 |
| **Apple MusicKit JS** | ✅ 전곡 | ✅ 가능 | ⭐⭐⭐⭐ 2순위 | 구독자만, 전곡재생 강제 |
| **Spotify Web Playback SDK** | ✅ 전곡 | △ 제한 | ⭐⭐ 3순위 | Premium만 + 신규앱 승인난망 |
| **Spotify 30초 미리듣기** | ❌ | ❌ **폐지** | ✖ | 2024.11 신규앱 차단 |
| **멜론/지니/유튜브뮤직** | ✅ | ❌ | ✖ | **공개 API 자체가 없음** |
| **자체 제작/로열티프리** | △ 대체 | ✅ | ⭐⭐⭐ 보조 | 유명곡 아님 |

**전략 요약: YouTube를 메인 엔진으로, Apple Music을 프리미엄 옵션으로. 자체 음원은 안전망.**

## 1. 각 서비스 상세 분석

### ✅ YouTube IFrame Player API — 우리 앱의 최적해

**왜 1순위인가**
- **신규 앱도 무료로, 승인 없이** 바로 쓸 수 있다. (Spotify/Apple과 결정적 차이)
- 로그인·구독 불필요 — 유저가 YouTube 계정 없어도 재생됨.
- 사실상 **세상의 모든 노래**가 유튜브에 있음(공식 음원, 뮤비, 안무 영상까지).
- **랜덤플레이댄스에 완벽**: K팝 안무 영상이 유튜브에 다 있음. 전주 퀴즈용 공식 음원도.

**어떻게 작동하나**
- `<iframe>`으로 유튜브 플레이어를 앱에 심고, JavaScript로 재생·정지·구간이동·볼륨 제어.
- 특정 시점부터 재생 가능(`start` 파라미터) → 전주 퀴즈에서 "3초만 듣기" 구현 가능.
- 재생 위치·상태를 이벤트로 받아 UI 갱신.

**제약 (반드시 지켜야 함)**
- **플레이어가 화면에 보여야 함**: 최소 200×200px 뷰포트 필요. 오디오만 숨겨서 트는 건 정책 위반.
  → 레크에선 오히려 장점: 대강당 화면에 안무 영상/뮤비를 띄우면 됨.
- 중첩 iframe으로 출처 숨기기 금지.
- 아동 대상 앱은 별도 규정(COPPA) — 우리는 대학생 대상이라 무관.
- EU 사용자는 쿠키 동의 필요.

**레크 게임별 활용**
- **랜덤플레이댄스**: 안무 영상 여러 개를 큐에 넣고, 랜덤 구간에서 전환. 화면에 영상 표시.
- **전주 퀴즈**: 공식 음원 영상을 `start`로 특정 구간 3초 재생 → 정지 → 정답.
- **떼창 퀴즈**: 후렴 구간으로 점프.

> **판정: 레크 앱의 메인 음악 엔진으로 확정.** 무료·무승인·전곡·안무영상까지 = 완벽.

### ✅ Apple MusicKit JS — 프리미엄 구독자용 2순위

**되는 것**
- 웹에서 **애플뮤직 전곡 재생** 가능. 플러그인 없이 모든 최신 브라우저.
- 개발자 토큰 발급받아 `musickit.js` 심으면 됨.
- 곡·앨범·플레이리스트를 큐에 넣고 재생/정지/스킵 제어.

**핵심 제약 (라이선스 계약서 3.3.6(D))**
- **애플뮤직 구독자만** 재생 가능. 유저가 로그인 후 구독 확인됨.
- **반드시 전곡 재생 활성화** — "30초만" 같은 부분재생 강제 불가. 표준 컨트롤(재생/정지/스킵) 제공 의무.
- **다운로드·업로드·수정 금지**, 다른 콘텐츠와 싱크 금지.
- MusicKit JS를 다른 JS와 재조합하거나 재호스팅 금지(독립 라이브러리로만).

**우리 시나리오에 중요한 실제 사례**
- 애플 개발자 포럼에 **정확히 우리 상황을 질문한 일본 개발자**가 있음:
  "호스트가 곡을 고르면, 같은 방의 다른 사람들이 각자 자기 애플뮤직 구독으로, 자기 기기에서 그 곡을 듣는다. 서버는 오디오를 저장/전송하지 않고 곡 ID와 재생 위치만 중계한다."
  → 이게 바로 **참가자 각자 기기에서 동기화 재생**하는 구조. 애플뮤직 약관상 각자 구독자면 가능한 방향.
  다만 **참가자 전원이 애플뮤직 구독자여야** 해서 레크 현실(참가자 접속 없음)엔 안 맞음.

**우리 앱에서의 현실적 용도**
- **진행자(호스트) 기기 하나만** 애플뮤직으로 재생 → 스피커로 출력. 이게 현실적.
- 참가자는 안 들어도 됨(우리 앱 철학: 참가자 접속 0).

> **판정: 진행자가 애플뮤직 구독자면 고음질 옵션으로 제공. 필수는 아닌 프리미엄 경로.**

### △ Spotify — 신규 앱엔 사실상 막힘

**무슨 일이 있었나**
- 2024년 11월 27일, Spotify가 신규 앱 대상으로 대거 API를 잘랐다:
  - **30초 미리듣기(preview_url) 폐지** — 수많은 음악 사이드프로젝트가 여기 의존했는데 하루아침에 막힘.
  - 추천, 오디오 분석, 에디토리얼 플레이리스트 등도 신규앱 차단.
- 2025년 5월엔 더 조여서, 의미있는 기능은 **월 25만 MAU를 넘겨야** 확장 접근 허용. 인디 개발자는 사실상 컷.

**아직 되는 것**
- **Web Playback SDK로 전곡 재생**은 여전히 가능. 단 **Spotify Premium 구독자만**, 로그인 필수.
- 검색, 트랙/앨범 조회, 재생 제어, 플레이리스트 관리는 유지.

**우리 앱 관점**
- 30초 미리듣기가 막힌 게 뼈아픔(전주 퀴즈에 이상적이었음).
- 전곡 재생은 되지만 Premium + 로그인 + 신규앱 승인 장벽.
- YouTube/Apple로 충분해서 **후순위**.

> **판정: 초기엔 스킵. 나중에 규모 커지면 Premium 유저용 옵션으로 재검토.**

### ✖ 멜론 / 지니 / 유튜브뮤직 / 바이브 — 공개 API 없음

- **국내 스트리밍(멜론·지니·플로·바이브)은 서드파티 개발자용 공개 재생 API가 없다.**
  기업 제휴(B2B)로만 열리고, 개인·인디 개발자는 접근 불가.
- **YouTube Music도 별도 재생 API 없음** — 유튜브 본체(IFrame API)로 우회하는 게 사실상 유일.
- 국내 유저 상당수가 멜론을 쓰지만, **연동 자체가 기술적으로 불가능**하니 기대 접어야 함.

> **판정: 연동 불가. 국내 서비스는 선택지에서 제외.**

---

### ⭐ 자체 제작 / 로열티프리 — 안전망

- 저작권 100% 자유로운 음원(로열티프리 라이브러리, 자체 제작 트랙).
- 유명곡은 아니지만 **어떤 API에도 안 의존** → 오프라인에서도 작동, 정책 리스크 0.
- **활용처**: 오프닝 배경음, 긴장감 BGM, 사운드보드(딩동댕/땡/환호), 시한폭탄 카운트다운.
- 이건 API 음악과 **별개로 항상 내장**해야 함(네트워크 없어도 사운드보드는 돌아야 하니까).

## 2. 레크마스터 음악 연동 최종 설계

### 3층 구조

```
[1층] 내장 사운드 (항상 작동, 오프라인 OK)
      · 사운드보드(딩동댕/땡/긴장/환호), 카운트다운, 룰렛 효과음
      · 로열티프리 or 자체 제작 → API·네트워크 불필요
      · 시한폭탄, 눈치게임 등 "효과음이면 충분한" 게임

[2층] YouTube 연동 (메인 음악 엔진, 무료·무승인)
      · 랜덤플레이댄스: 안무 영상 큐 → 랜덤 구간 전환, 화면 표시
      · 전주 퀴즈: 공식 음원 start 파라미터로 구간 재생
      · 진행자가 곡/영상 검색해서 큐에 추가
      · 대강당 화면에 영상 띄우면 정책(화면 노출)도 자연 충족

[3층] Apple Music 연동 (프리미엄 옵션)
      · 진행자가 애플뮤직 구독자면 고음질 전곡 재생
      · 로그인 → 검색 → 큐 → 재생. 광고 없음.
      · 없어도 2층으로 충분 → 선택 기능
```

### 게임별 음악 소스 매핑

| 게임 | 음악 필요도 | 추천 소스 |
|---|---|---|
| 랜덤플레이댄스 | 필수 | **YouTube**(안무 영상) |
| 노래 전주 퀴즈 | 필수 | **YouTube**(공식 음원 구간) |
| 떼창 퀴즈 | 필수 | **YouTube** or Apple |
| 시한폭탄 | 효과음만 | **내장 사운드** |
| 벌칙 룰렛 | 효과음만 | **내장 사운드** |
| 사운드보드(전 게임) | 효과음 | **내장 사운드** |
| 오프닝/피날레 BGM | 분위기 | 내장 or YouTube |

## 3. 구현 시 주의점 & 리스크

1. **YouTube 플레이어는 화면에 보여야 함.**
   → 레크에선 자연스러움: 대강당 화면/노트북에 영상 띄우기. 오디오만 숨기면 정책 위반.

2. **모바일 자동재생 제약.**
   → iOS/안드로이드 브라우저는 사용자 탭 없이 소리 자동재생을 막음. "재생" 버튼을 진행자가 직접 누르는 UX로 설계(어차피 진행자가 통제하니 OK).

3. **네트워크 의존.**
   → 2·3층은 인터넷 필요. MT 장소가 와이파이 약할 수 있음. **1층 내장 사운드는 오프라인 보장**해서 최소한의 재미는 항상 확보.

4. **정책 변동 리스크.**
   → Spotify 사례처럼 API 정책은 언제든 바뀜. 특정 서비스에 올인하지 말고 **YouTube 메인 + 내장 사운드 안전망** 이중화.

5. **저작권 안전지대.**
   → 우리가 음원을 **저장·재호스팅·다운로드하지 않고**, 각 서비스의 공식 플레이어로 **재생만** 하면 안전. 절대 음원 파일을 서버에 올리지 말 것.

## 4. 개발 우선순위

```
MVP:  1층(내장 사운드) + 2층(YouTube) 
      → 이것만으로 모든 음악 게임 커버, 무료·무승인
다음:  3층(Apple Music) 프리미엄 옵션
보류:  Spotify (규모 커진 뒤 재검토), 국내 스트리밍 (연동 불가)
```

> **한 줄 결론:**
> "YouTube IFrame API를 메인 음악 엔진으로 쓰고(무료·무승인·전곡·안무영상), 내장 사운드로 오프라인 안전망을 깔고, Apple Music은 구독 진행자용 고음질 옵션으로 얹는다. Spotify 30초 미리듣기는 폐지됐고 국내 스트리밍은 API가 없으니 기대하지 않는다."
