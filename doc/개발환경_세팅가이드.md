# 개발환경 세팅 가이드 — M1 MacBook (8GB)

> RecPlus 개발에 필요한 것 **전부**. 위에서부터 순서대로 복붙하면 된다. 총 30~60분.
> 8GB 램 기준으로 **안 깔아도 되는 건 뺐다**. (Docker·Xcode 본체·Python·시뮬레이터 전부 불필요)

---

## 0. 시작 전 확인

```bash
sw_vers                 # macOS 버전
df -h /System/Volumes/Data | tail -1   # 디스크 여유 확인
uname -m                # arm64 나와야 정상 (M1)
```

**디스크는 20GB 이상 비워두자.** node_modules + 빌드 캐시가 프로젝트당 1~2GB 먹는다.

---

## 1. Xcode Command Line Tools — 컴파일러·git 기본

```bash
xcode-select --install
```

창이 뜨면 설치. **Xcode 본체(15GB)는 필요 없다.** CLT만(약 1.5GB). 웹 개발엔 이걸로 충분하다.

확인:
```bash
xcode-select -p        # /Library/Developer/CommandLineTools
git --version
```

---

## 2. Homebrew — 맥용 패키지 매니저

```bash
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
```

설치 후 PATH 등록 (Apple Silicon은 `/opt/homebrew`에 깔린다):
```bash
echo 'eval "$(/opt/homebrew/bin/brew shellenv)"' >> ~/.zprofile
eval "$(/opt/homebrew/bin/brew shellenv)"
brew --version
```

---

## 3. Git + GitHub — 코드 이력과 배포의 출발점

```bash
brew install git gh
git config --global user.name "돈희"
git config --global user.email "본인이메일@example.com"
git config --global init.defaultBranch main
git config --global pull.rebase true
```

GitHub 로그인 (브라우저로 인증됨. SSH 키 따로 안 만들어도 된다):
```bash
gh auth login
# → GitHub.com / HTTPS / Y / Login with a web browser
```

확인:
```bash
gh auth status
```

> **왜 필요한가**: Vercel이 GitHub 저장소를 보고 자동 배포한다. push만 하면 배포되는 구조라 CLI 배포 명령이 아예 필요 없어진다.

---

## 4. Node.js — fnm으로 설치 (nvm보다 훨씬 빠르고 가볍다)

```bash
brew install fnm
echo 'eval "$(fnm env --use-on-cd --shell zsh)"' >> ~/.zshrc
source ~/.zshrc
```

LTS 설치 + 기본값 지정:
```bash
fnm install --lts
fnm default lts-latest
node -v      # v24.x 계열
npm -v
```

> Node를 brew로 직접 깔지 않는 이유: 나중에 버전 올리거나 프로젝트마다 다른 버전을 쓸 때 지옥이 된다. fnm은 `.node-version` 파일 보고 폴더 들어갈 때 자동 전환해준다.

---

## 5. pnpm — 패키지 매니저 (8GB/디스크 절약의 핵심)

```bash
corepack enable pnpm
pnpm -v
```

안 되면:
```bash
brew install pnpm
```

> **왜 npm이 아니라 pnpm인가**: 프로젝트 여러 개를 만들어도 패키지 실물을 한 군데만 저장하고 링크로 연결한다. 디스크가 몇 GB 단위로 절약되고 설치도 빠르다. 브리프 5항의 지침이기도 하다.

가끔 캐시 정리:
```bash
pnpm store prune
```

## 6. 에디터

둘 중 하나. **바이브코딩 중심이면 VS Code로 충분하다** (Cursor는 램을 더 먹는다).

```bash
brew install --cask visual-studio-code
# 또는
brew install --cask cursor
```

터미널에서 `code .` 쓰려면: VS Code 실행 → `Cmd+Shift+P` → "Shell Command: Install 'code' command in PATH"

**확장은 이 4개만** (많이 깔면 8GB에서 체감된다):
- ESLint
- Prettier - Code formatter
- Tailwind CSS IntelliSense
- Error Lens

## 7. Claude Code — 실제 개발을 굴리는 도구

```bash
npm install -g @anthropic-ai/claude-code
claude --version
```

프로젝트 폴더에서 `claude` 치면 시작. 처음 한 번 로그인한다.

**첫 세팅 팁**
- 프로젝트 루트에 `CLAUDE.md`를 만들어 컨벤션·구조·하지 말 것을 적어둔다. 매 세션 자동으로 읽힌다
- `doc/` 폴더의 브리프와 실행계획을 `CLAUDE.md`에서 링크로 가리켜두면 맥락이 안 끊긴다

## 8. 프로젝트 생성

```bash
mkdir -p ~/toy_proj && cd ~/toy_proj
pnpm create next-app@latest recplus
```

물어보는 것들 답:

| 질문 | 답 |
|---|---|
| TypeScript | **Yes** |
| ESLint | **Yes** |
| Tailwind CSS | **Yes** |
| `src/` directory | **Yes** |
| App Router | **Yes** |
| Turbopack | **Yes** (개발 서버가 눈에 띄게 빠르다) |
| import alias | **Yes** → `@/*` |

실행:
```bash
cd recplus
pnpm dev
```
→ http://localhost:3000

**저장소 연결** (한 번만):
```bash
gh repo create recplus --private --source=. --remote=origin --push
```

> 기존 `~/toy_proj/RecPlus/doc/` 문서들은 이 프로젝트의 `doc/`으로 옮겨서 같이 커밋해두자. 문서와 코드가 한 저장소에 있어야 맥락이 안 흩어진다.

## 9. Vercel 배포 — CLI 없이

1. https://vercel.com 접속 → **GitHub 계정으로 로그인**
2. Add New → Project → `recplus` 저장소 Import
3. 설정 그대로 두고 Deploy

이후로는 **`git push`만 하면 자동 배포**된다. PR을 올리면 미리보기 URL도 자동 생성.

> CLI(`vercel`)는 안 깔아도 된다. 램과 디스크를 아끼자.

## 10. 프로젝트에 추가로 넣을 패키지

프로젝트 만든 뒤 한 번에:
```bash
pnpm add zustand howler html-to-image
pnpm add -D @types/howler vitest @serwist/next serwist
```

| 패키지 | 용도 |
|---|---|
| `zustand` | 상태 관리 + localStorage 영속화 (진행 중 상태 복구) |
| `howler` | 사운드보드 — 오프라인 재생 보장 |
| `html-to-image` | 9:16 결과 카드 PNG 생성 |
| `serwist` | PWA 오프라인 캐시 |
| `vitest` | 추천엔진·랜덤소진 테스트 |

**폰트 (Pretendard)** — CDN 쓰면 오프라인에서 깨진다. 직접 넣자.
```bash
mkdir -p public/fonts
# https://github.com/orioncactus/pretendard 릴리스에서
# PretendardVariable.woff2 받아서 public/fonts/ 에 저장
```
`next/font/local`로 불러 쓴다.

## 12. 8GB 램에서 살아남는 법

| 항목 | 지침 |
|---|---|
| **Docker** | **절대 설치하지 말 것.** Supabase 로컬 개발도 마찬가지 — 클라우드에 직접 연결한다 |
| 개발 미리보기 | **Safari** 사용. 크롬은 탭당 램을 훨씬 먹는다 |
| dev 서버 | Turbopack 켜기 (`pnpm dev`에 이미 포함) |
| 프로젝트 | 동시에 하나만 `pnpm dev` 실행 |
| VS Code | 확장 최소, 창은 하나만 |
| 캐시 관리 | 가끔 `pnpm store prune` + `rm -rf .next` |
| Spotlight | 시스템 설정 → Spotlight → 개인정보 보호에 `node_modules` 포함 폴더 추가 (인덱싱 제외) |
| 모니터링 | 활성 상태 보기 → 메모리 → **메모리 압력 그래프가 녹색이면 정상** |

메모리 잡아먹는 것 확인:
```bash
ps aux | sort -nrk 4 | head -10
```

## 자주 막히는 지점

| 증상 | 원인 / 해결 |
|---|---|
| `command not found: brew` | PATH 등록 누락 → 2번의 `~/.zprofile` 줄 다시 실행 후 터미널 재시작 |
| `command not found: node` | fnm 초기화 누락 → 4번의 `~/.zshrc` 줄 확인 후 `source ~/.zshrc` |
| `corepack: command not found` | `brew install pnpm`으로 대체 |
| `pnpm dev`가 3000 포트 충돌 | 이미 떠 있는 것 → `lsof -ti:3000 \| xargs kill` |
| 설치가 계속 느림 | 디스크 여유 확인. 10GB 밑이면 스왑 때문에 전체가 느려진다 |
